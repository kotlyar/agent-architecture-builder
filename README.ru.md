Agent Architecture Builder — метод проектирования агентных систем на основе
реальной работы, а не названий профессий или модных компонентов.

Навык проводит понятное исследовательское интервью, восстанавливает конкретные
рабочие случаи и по явным условиям определяет, что должно быть обычным процессом,
инструментом, навыком, временным подагентом, постоянным профилем или
оркестратором. После завершения проектирования он создаёт самодостаточный
комплект, который другой агент может реализовать и проверить.

Критерии выбора не зависят от платформы. Текущие шаблоны поставки и установки
рассчитаны на Hermes и Codex; поддержку других сред можно добавлять отдельными
адаптерами, не меняя основную модель решений.

## Какую проблему решает проект

Агентные системы часто разделяют слишком рано:

- каждую профессию превращают в агента;
- под каждую рекламную или рабочую площадку создают отдельного агента;
- оркестратор добавляют до появления реальной задачи координации;
- панель в браузере и базу выбирают до выяснения рабочих потребностей;
- большую инструкцию ошибочно принимают за отдельного владельца результата и
  состояния.

Этот проект начинает с желаемого изменения и выясняет, как работа выполняется в
реальности. Архитектура определяется после этого.

```text
желаемое изменение
  → реальные рабочие случаи
  → отдельные функции
  → способ выполнения
  → границы состояния и полномочий
  → профили
  → оркестрация, только если она доказана
  → комплект для реализации
```

## Основные правила

Всегда выбирается самая простая достаточная форма:

```text
обычный процесс → инструмент → навык → подагент → профиль → оркестратор
```

Отдельный постоянный профиль допустим только при выполнении всех трёх условий
профиля и хотя бы одного условия изоляции:

```text
профиль = P1 И P2 И P3 И (I1 ИЛИ I2 ИЛИ I3 ИЛИ I4 ИЛИ I5 ИЛИ I6)
```

- `P1` — владеет долгоживущим результатом или классом решений;
- `P2` — владеет сохраняемым состоянием: списком работ, историей решений или
  рабочим состоянием;
- `P3` — имеет независимый запуск, паузу, повтор, восстановление и завершение;
- `I1–I6` — учётная запись, полномочия, данные, порядок работы, контекст или
  постоянная нагрузка требуют изоляции.

Оркестратор на основе языковой модели допустим только при выполнении четырёх
условий:

```text
оркестратор_на_модели = O1 И O2 И O3 И O4
```

- `O1` — доказано не менее двух самостоятельных профилей;
- `O2` — они создают один общий составной результат;
- `O3` — требуется распределять ресурсы, управлять зависимостями, разрешать
  противоречия или собирать единое решение;
- `O4` — координация требует смыслового выбора и не сводится к фиксированным
  правилам.

Если `O4` не пройдено, используется обычный маршрутизатор. Неизвестное условие
считается непройденным.

## Как проходит интервью

Пользователю не нужно знать терминологию агентных систем. Навык задаёт по одному
главному вопросу за ход:

- Что должно измениться после запуска системы?
- Почему это стало важно именно сейчас?
- Как эта работа выполнялась в последний раз?
- Какие сведения использовались и кому передавался результат?
- Что необходимо помнить через неделю?
- Перед каким точным действием нужно получить подтверждение?
- Где удобнее ставить задачи, видеть ход работы и принимать решения?

Если человеку трудно перечислить возможные работы, навык показывает
необязательные подсказки. Например, для SEO это могут быть аудит страниц,
рекомендации по улучшению, исследование спроса, подготовка материалов, ведение
списка работ и измерение результата. Выбранные пункты не становятся архитектурой
автоматически — они проверяются на реальном рабочем случае.

## Управление и хранение

Навык отдельно выясняет удобный способ контроля: разговор, командная строка,
панель в браузере, API, уведомления или обоснованное сочетание.

Панель в браузере предлагается, только если подтверждены общая очередь,
структурированные подтверждения, сводное отображение большого числа состояний,
история действий или работа людей без технической подготовки. Для первой версии
используется бесплатный набор с открытым исходным кодом: React, TypeScript, Vite,
Tailwind CSS и shadcn/ui.

Хранилище выбирается независимо. Файлы, SQLite, PostgreSQL, смысловой поиск или
отсутствие новой базы сравниваются по одновременной записи, транзакциям, сроку
хранения, приватности, поиску и стоимости эксплуатации.

## Итог работы навыка

После прохождения условий готовности создаются каталог и архив `.zip`, которые
содержат:

- корневой `AGENTS.md`;
- единую инструкцию `IMPLEMENTATION.md` для Codex или Hermes;
- требования и основания;
- решения по архитектуре и полномочиям;
- критерии приёмки и сквозные случаи;
- заготовки профилей, навыков, инструментов, процессов, хранилища и интерфейса;
- дистрибутив каждого выбранного профиля Hermes;
- манифест и контрольные суммы SHA-256.

Упаковщик отклоняет черновики, критически важное неизвестное, неполные
дистрибутивы и файлы, похожие на ключи или закрытое рабочее состояние.

## Установка

Интерактивная установка через общую для разных агентов команду:

```bash
npx skills add kotlyar/agent-architecture-builder
```

GitHub CLI версии 2.90.0 или новее позволяет найти и установить любую языковую
версию:

```bash
gh skill install kotlyar/agent-architecture-builder
```

Ручная установка локально в проект Hermes:

```bash
mkdir -p .hermes/skills
cp -R skills/hermes-agent-builder .hermes/skills/
```

Для Codex:

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
cp -R skills/hermes-agent-builder "${CODEX_HOME:-$HOME/.codex}/skills/"
```

После установки начните новый сеанс, чтобы среда обнаружила навык.

## Пример запроса

```text
Используй $hermes-agent-builder и помоги спроектировать агентную систему для
маркетинга. Сначала проведи интервью простыми вопросами. Не определяй число
агентов, пока не поймёшь желаемый результат и хотя бы один реальный рабочий
случай.
```

Для начинающей маркетинговой системы наиболее вероятная первая версия — один
профиль маркетолога с навыками SEO и платного продвижения. Отдельные профили SEO
и платного продвижения появляются только при собственных результатах,
сохраняемом состоянии и жизненных циклах. Яндекс Директ и Google Ads обычно
начинаются как навыки и инструменты, а не как агенты.

## Проверка

```bash
python scripts/validate_repository.py
```

Проверка использует только стандартную библиотеку Python, проверяет обе языковые
версии и запускает испытания упаковщиков.

## Текущая граница

Модель архитектурных решений применима к разным агентным системам. Готовые файлы
дистрибутивов и прямые команды установки пока рассчитаны на Hermes, а передача
задания на реализацию поддерживает Hermes и Codex. Для другой среды потребуется
адаптер поставки, но не новая модель определения архитектуры.
