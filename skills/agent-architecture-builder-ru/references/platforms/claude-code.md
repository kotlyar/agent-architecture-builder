# Адаптер реализации для Claude Code

Читай этот файл только тогда, когда Claude Code выбран целевой средой. Применяй
его после завершения независимой от платформы архитектуры.

## Соответствия

- Постоянные правила проекта: `CLAUDE.md` и правила с областью действия по путям.
- Навыки: `.claude/skills/<имя-навыка>/SKILL.md` для проекта или
  `~/.claude/skills/<имя-навыка>/SKILL.md` для пользователя.
- Пользовательские подагенты: `.claude/agents/<имя-агента>.md` для проекта или
  `~/.claude/agents/<имя-агента>.md` для пользователя. Обязательны `name` и
  `description`; инструменты, навыки, память, изоляцию и модель добавляй только
  по требованиям нейтральной архитектуры.
- Распространяемые наборы: `.claude-plugin/plugin.json`, а каталоги `skills/`,
  `agents/`, обработчики событий и MCP располагаются в корне плагина.
- Внешние системы: MCP и инструменты с явными границами полномочий.

Определение подагента Claude Code создаёт специализированный изолированный
контекст. Оно не создаёт автоматически рабочую очередь, событие запуска,
долговременное состояние или восстановление. Если нейтральная архитектура
требует постоянного агента, реализуй эти части отдельно, используя Claude Code
как одну из сред исполнения.

Используй навык для повторяемого знания или метода в текущем контексте, а
подагента — для ограниченной изолированной работы. Если маршрутизация полностью
задаётся правилами, используй обычный процесс. Смысловое согласование добавляй
только после прохождения условий оркестратора.

Перед реализацией сверь поля и поведение плагинов с актуальной официальной
документацией Claude Code.
