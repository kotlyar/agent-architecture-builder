# Адаптер реализации для Codex

Читай этот файл только тогда, когда Codex выбран целевой средой. Применяй его
после завершения независимой от платформы архитектуры.

## Соответствия

- Постоянные правила проекта: `AGENTS.md`, при необходимости с областью действия
  по каталогам.
- Навыки: `.agents/skills/<имя-навыка>/SKILL.md` для проекта или
  `~/.agents/skills/<имя-навыка>/SKILL.md` для пользователя.
- Пользовательские подагенты: `.codex/agents/<имя-агента>.toml` для проекта или
  `~/.codex/agents/<имя-агента>.toml` для пользователя. Обязательны `name`,
  `description` и `developer_instructions`.
- Настройки агентов и исполнения: `.codex/config.toml` или пользовательская
  конфигурация.
- Внешние системы: MCP и инструменты с раздельными правами чтения и записи, если
  риски различаются.

В комплекте добавь таблицу соответствия каждого нейтрального компонента точному
файлу или службе Codex, зависимостям, способу запуска, полномочиям и проверке.
Все навыки из манифеста должны получить отдельный каталог `SKILL.md`, а каждая
операция инструмента — отдельный проверяемый контракт, даже если один MCP-сервер
реализует несколько операций.

В создаваемом `AGENTS.md` обязателен раздел «Готовность к работе». Он перечисляет
зависимости из `requirements/startup-readiness.json`, названия параметров и
безопасные ссылки на секреты, команду проверки и правило: до успешной проверки
предметная работа запрещена, разрешены только настройка и безопасная диагностика.
Значения паролей и токенов в `AGENTS.md` не помещаются. Проверка должна
подтверждать нужную учётную запись, область и минимальные права, а не только
наличие переменной окружения.

Файл пользовательского агента Codex описывает специализированный запускаемый
сеанс, но сам не создаёт постоянную очередь, расписание или владельца состояния.
Если нейтральная архитектура требует постоянного агента, отдельно реализуй его
событие запуска, хранилище, жизненный цикл, восстановление и рабочую границу. Не
принимай TOML-файл за целого агента.

Используй подагентов Codex для ограниченной порученной работы. Для устойчивых
правил маршрутизации используй обычную программу или процесс. Поручай главному
агенту смысловое согласование только после прохождения условий оркестратора.

Перед реализацией сверь пути и поддерживаемые поля с актуальной официальной
документацией Codex: формат пользовательских агентов может меняться.
