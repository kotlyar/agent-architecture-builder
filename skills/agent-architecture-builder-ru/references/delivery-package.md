# Универсальный комплект реализации

Создавай комплект только после завершения исследования и архитектурных решений.
Он должен отделять независимый от платформы проект от адаптеров реализации.
Получивший комплект агент должен реализовать систему без доступа к породившему
её разговору.

## Обязательная структура

```text
<система>-implementation-kit/
├── START-HERE.md
├── IMPLEMENTATION.md
├── IMPLEMENTER-RULES.md
├── manifest.json
├── requirements/
│   ├── goal.md
│   ├── work-map.md
│   └── constraints.md
├── architecture/
│   ├── platform-neutral.md
│   ├── system.md
│   ├── decisions.md
│   ├── authority.md
│   └── interface-and-storage.md
├── platforms/
│   └── <платформа>/README.md
├── blueprint/
│   ├── project-tree.md
│   └── components/<компонент>.md
├── acceptance/
│   ├── criteria.md
│   └── scenarios.md
├── evidence/sources.md
└── unresolved.md
```

Нейтральная архитектура является источником истины для границ компонентов.
Адаптер объясняет, как выразить эти решения в выбранной среде, и не вправе
скрыто добавлять, удалять, объединять или разделять компоненты.

## Манифест версии 2

```json
{
  "schema_version": 2,
  "system_slug": "example-agent-system",
  "status": "ready_for_implementation",
  "target_platforms": [
    {
      "slug": "codex",
      "adapter": "platforms/codex/README.md"
    }
  ],
  "entrypoint": "START-HERE.md",
  "implementation_instruction": "IMPLEMENTATION.md",
  "critical_unknowns": [],
  "components": [
    {
      "slug": "example-worker",
      "kind": "persistent-agent",
      "specification": "blueprint/components/example-worker.md"
    }
  ],
  "expected_results": [
    "implementation/",
    "implementation/IMPLEMENTATION-RESULT.md"
  ]
}
```

Имена платформ не ограничены встроенным перечнем. Для каждой выбранной среды
обязателен локальный файл адаптера. Допустимые виды компонентов:

`deterministic-workflow | tool | skill | subagent | persistent-agent | orchestrator | storage | interface`

## Содержание

- `START-HERE.md` — состояние, способ передачи комплекта любому реализующему
  агенту и выбранные платформы.
- `IMPLEMENTATION.md` — полное задание, порядок чтения, каталог результата,
  проверки и условия остановки.
- `IMPLEMENTER-RULES.md` — короткие независимые от платформы правила. Постоянные
  инструкции конкретной среды находятся в адаптерах.
- `requirements/` — желаемый результат, признаки успеха, рабочие случаи,
  исходные данные, ограничения и критические неизвестные.
- `architecture/platform-neutral.md` — компоненты и связи без названий файлов и
  терминов конкретного продукта.
- `architecture/decisions.md` — таблица решений, основания, отвергнутые варианты
  и условия пересмотра.
- `architecture/authority.md` — инструменты, учётные записи, права чтения и
  записи, подтверждения, повторы и журнал действий.
- `architecture/interface-and-storage.md` — управление, владельцы состояния,
  хранилище, срок хранения, одновременная работа и восстановление.
- `platforms/<платформа>/README.md` — точное соответствие файлов, конфигурация,
  установка, запуск и проверки выбранной среды.
- `blueprint/components/` — одна спецификация для каждого компонента манифеста.
- `acceptance/` — наблюдаемые критерии и сквозные сценарии.
- `unresolved.md` — некритичные неизвестные, владелец, срок, запасной вариант и
  событие пересмотра. Критические неизвестные также находятся в манифесте и
  блокируют упаковку.

## Условия готовности

- `R1 Цель`: явно заданы желаемое изменение, получатель, признаки успеха и то,
  что не входит в систему.
- `R2 Работа`: каждая важная функция подтверждена реальным или конкретным
  ожидаемым случаем.
- `R3 Архитектура`: у каждой функции есть способ выполнения и владелец; решения
  по агентам и оркестратору записаны.
- `R4 Состояние и полномочия`: заданы владельцы состояния, права, подтверждения,
  повторы и границы сбоев.
- `R5 Интерфейс и хранилище`: каждый выбор обоснован наблюдаемой потребностью.
- `R6 Платформа`: выбрана хотя бы одна среда и создан полный адаптер.
- `R7 Приёмка`: проверяемы обычное поведение, сбои, восстановление и полномочия.
- `R8 Передача`: агент может реализовать систему только по комплекту.

Неизвестное означает, что условие не пройдено. Не упаковывай черновик ради вида
готовности.

## Упаковка

Скопируй шаблоны из `assets/`, замени все примеры, установи `schema_version: 2`
и оставь `critical_unknowns` пустым только при наличии оснований. Запусти:

```bash
python scripts/package_delivery.py <каталог-комплекта>
```

Упаковщик проверяет обязательные файлы, спецификации компонентов, адаптеры
платформ, секреты, символические ссылки и готовность, после чего создаёт архив с
контрольными суммами вне исходного каталога.
